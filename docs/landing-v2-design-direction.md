# HorseSharing Bishkek Landing v2 Design Direction

Дата: 2026-09-07  
Статус: дизайн-направление, без правки кода

## 1. Что меняем в подходе

Текущий лендинг уже правильно пытается вести в Telegram-заявку, но визуально он все еще похож на туристическую витрину: большое затемненное фото, крупный заголовок, красивые секции ниже. Для v2 нужно сделать не "лендинг про лошадей", а нормальную продуктовую страницу бронирования.

Главная мысль:

```text
Пользователь должен за первые 5-8 секунд понять: где кататься, сколько стоит, когда можно, подходит ли новичкам и куда нажать.
```

V2 должен выглядеть ближе к Airbnb/OpenTable/Fresha, а не к Dribbble-странице outdoor-тура. Красота нужна, но она должна помогать выбору маршрута.

## 3. UI principles for v2

1. Booking intent выше настроения. Фото гор нужны, но форма выбора и коммерческие факты важнее.
2. Факты раньше прилагательных. Сначала цена, длительность, локация, уровень, подтверждение; потом красивый текст.
3. Один главный сценарий: выбрать маршрут и уйти в Telegram. Все вторичные ссылки не должны конкурировать с этим.
4. Не притворяться мгновенным маркетплейсом. Если слот подтверждает менеджер, так и писать.
5. Карточки должны сравниваться. Одинаковый порядок полей: фото, маршрут, цена, длительность, уровень, ближайшее время, CTA.
6. Каждый блок закрывает конкретный страх: "дорого?", "я новичок?", "где встреча?", "безопасно?", "можно с детьми?", "как оплатить?"
7. Не использовать fake trust. Нет проверенных отзывов - нет звездного рейтинга как будто он уже есть.
8. Меньше декоративных слоев. Никаких карточек внутри карточек, лишних теней, больших градиентов, размытых фонов.
9. Текст короткий. Пользователь не читает бренд-манифест, он выбирает прогулку.
10. Mobile-first важнее desktop-wow. Основная аудитория придет с телефона и уйдет в Telegram.

## 4. First viewport

### Цель первого экрана

Первый экран должен работать как мини-форма бронирования:

- `Конные прогулки в Бишкеке`
- `от 1 500 сом/чел`
- `1-2 часа`
- `Чункурчак и Аламедин`
- `для новичков`
- быстрый выбор даты/локации/участников/длительности
- CTA `Записаться в Telegram`
- пояснение `Бронь подтверждает менеджер`

### Desktop layout

Схема:

1. Верхняя навигация компактная: бренд, `Маршруты`, `Как проходит`, `FAQ`, CTA.
2. Первый экран делится на две рабочие зоны:
   - слева: H1, короткий текст, facts row, primary CTA;
   - справа или снизу в широкой панели: booking picker.
3. Фото должно быть видно в первом экране, но не должно съедать весь экран. Лучше использовать photo panel / media column, чем темный full-bleed hero.
4. Booking picker должен быть на первом экране без скролла:
   - `Когда`: сегодня, завтра, выходные;
   - `Локация`: Чункурчак, Аламедин;
   - `Участники`: 1, 2, 3-6;
   - `Длительность`: 1 час, 1.5 часа, 2 часа;
   - CTA `Проверить время в Telegram`.
5. Под picker мелко: `Свободное время и точку встречи подтвердит менеджер`.

Что не делать:

- не делать hero на 86-100vh, где до picker нужно скроллить;
- не прятать цену ниже первого экрана;
- не ставить большую "атмосферную" фразу вместо конкретного выбора;
- не делать вторичный CTA визуально равным Telegram CTA.

### Mobile layout

Порядок на 360-430 px:

1. Header: `HorseSharing` + маленькая кнопка `Telegram`.
2. H1: `Конные прогулки в Бишкеке`.
3. Facts row в 2 строки: `от 1 500 сом`, `1-2 часа`, `Чункурчак`, `для новичков`.
4. Primary CTA: `Записаться в Telegram`.
5. Booking picker как компактный блок с tappable chips.
6. Одна сильная карточка маршрута или горизонтальный scroll из 2-3 маршрутов.
7. Фото/галерея ниже, не вместо формы.

Sticky bottom bar после первого скролла:

```text
от 1 500 сом · 1-2 часа
Записаться
```

На mobile нельзя начинать с огромной картинки и текста поверх нее. Пользователь должен сразу попасть в выбор.

## 5. Visual system

### Общий тон

Тон: локальный сервис бронирования, а не премиальный туроператор и не SaaS-стартап. Интерфейс должен быть спокойным, плотным, уверенным.

Хорошее ощущение:

- реальные маршруты рядом с Бишкеком;
- понятная цена;
- менеджер на связи;
- можно новичкам;
- бронь не теряется после клика.

Плохое ощущение:

- "красивая обложка, а что делать непонятно";
- слишком темный hero;
- туристические лозунги;
- фейковая роскошь;
- много декоративных бейджей.

### Color

Рекомендация:

- base: почти белый / warm off-white для фона;
- text: темный, почти черный зеленовато-серый;
- border: нейтральный серый;
- primary CTA: Telegram blue или уверенный темный action color;
- secondary accents: приглушенный clay / mountain green;
- не строить весь дизайн только на зеленом/бежевом.

Фото должны давать основной outdoor-характер. Цвет интерфейса не обязан изображать природу.

### Typography

Inter можно оставить. Главное - поменять масштаб:

- H1 на desktop не больше 52-64 px;
- H1 на mobile 32-40 px;
- section headings 28-40 px;
- карточки 16-22 px;
- line-height спокойный, без плотного hero-постера.

Не использовать гигантский headline как главный визуальный прием.

### Components

- Buttons: 48-52 px высотой, radius до 8 px, один primary style.
- Chips: для даты, людей, длительности, уровня.
- Route cards: фото 4:3 или 3:2, ниже плотные facts.
- Icons: только для быстрых фактов и действий; не украшать каждый абзац.
- Cards: только для маршрутов, picker, отзывов и admin-таблиц. Секции не превращать в большие плавающие карточки.
- Map/location: простая карта или static location block с 2GIS links. Не делать декоративную псевдокарту.

### Imagery

Нужны реальные фото:

- человек + лошадь + понятная локация;
- фото маршрута днем, без сильного затемнения;
- отдельные фото лошади/инструктора для trust;
- кадры в мобильном кропе должны оставаться понятными.

Не использовать:

- темные blurred background;
- stock-like горы без лошадей;
- фото, где нельзя понять услугу;
- чужие изображения без прав как production proof;
- map screenshots как эмоциональный hero.

## 6. Что убрать из текущего дизайна

1. Full-bleed dark hero как основную композицию. Он делает страницу похожей на travel poster, а не на booking product.
2. Слишком большой H1. Он занимает внимание, но не помогает выбрать маршрут.
3. Отдельную searchBand ниже hero как главный picker. В v2 picker должен быть внутри first viewport.
4. Hero stats в виде декоративной панели. Эти данные лучше превратить в facts row рядом с CTA и в поля picker.
5. Видимый English SEO line в hero. Английский можно оставить ниже или в metadata, но на первом экране он снижает локальную ясность.
6. Секции с большим количеством воздуха и абстрактным tone-of-voice. Нужна плотность, как у booking/listing продукта.
7. Proof-блок со звездой, если нет проверенных отзывов. Лучше честно показать: фото, 2GIS/Instagram источники, статус проверки.
8. Однотипные карточки маршрутов без ближайших времен и конкретных ограничений.
9. Декоративные accent colors, которые спорят между собой. Оставить один action color и 1-2 спокойных вспомогательных цвета.
10. Любой текст, который звучит как обещание мгновенной брони, если подтверждение ручное.

## 7. Route cards v2

Карточка маршрута должна отвечать на выбор, а не просто показывать фото.

Порядок:

```text
[Фото]
Чункурчак, прогулка 1 час
Чункурчак · 25-40 мин от Бишкека
от 1 500 сом/чел
1 час · до 6 человек · новичкам можно
Ближайшее время: 10:00, 13:00, 16:00
Менеджер подтвердит слот
[Выбрать время]
```

Если точных слотов нет, писать:

```text
Время уточним в Telegram
```

Не писать:

```text
Свободно сегодня
```

если это не связано с реальным наличием лошадей и инструктора.

## 8. Editorial / blog sections

Editorial нужен для SEO и доверия, но он не должен перетягивать страницу в блог.

Форматы:

- `Где покататься на лошадях рядом с Бишкеком`
- `Чункурчак или Аламедин: что выбрать новичку`
- `Что надеть на конную прогулку`
- `Можно ли детям`
- `Сколько стоит horse riding в Бишкеке`

Правило: каждая статья или guide-card должна вести обратно к выбору маршрута.

Карточка editorial:

```text
Чункурчак или Аламедин
Коротко: Чункурчак ближе к горным видам, Аламедин спокойнее для первого раза.
5 минут чтения
[Посмотреть маршруты]
```

Не делать lifestyle-блог с красивыми заголовками без пользы.

## 9. Simple admin direction

Админка нужна не как отдельный красивый продукт, а как рабочая панель для владельца/менеджера.

Брать из Mixpanel/Dub/Shopify/Google Analytics:

- верхний ряд метрик;
- один главный график;
- таблица источников;
- таблица последних заявок;
- фильтр периода;
- понятные пустые состояния.

Минимальная структура:

```text
Visits
Telegram clicks
Bot starts
Bookings
Visit -> Telegram conversion
Telegram -> Booking conversion
```

Ниже:

```text
График за 7 / 30 дней
Источники: SEO, Instagram, Telegram channels, ads
Последние заявки
Маршруты по спросу
Ошибки attribution / missing bot start
```

Визуально:

- белый фон;
- тонкие границы;
- маленькие headings;
- таблицы важнее карточек;
- без gradient hero, иллюстраций и маркетинговых секций.

## 10. Mobile-first Telegram audience

Для Бишкекской аудитории v2 должен считать телефон главным устройством.

### Поведение

- Все основные CTA ведут в Telegram bot deep link.
- После выбора chips на сайте deep link должен по возможности передавать выбранный сценарий.
- Если сайт не передает значения в бот, не показывать ложное состояние "подобрано".
- В CTA писать действие честно: `Проверить время в Telegram`, `Записаться в Telegram`, `Спросить менеджера`.
- Нужен fallback контакта: телефон/WhatsApp можно показать ниже как trust, но не ломать главный Telegram flow.

### Mobile UI

- Размер tap targets минимум 44-48 px.
- Кнопка Telegram всегда видна в первом экране.
- Sticky bottom CTA включать после того, как пользователь проскроллил hero.
- Picker не должен требовать ввода текста. Только chips/segmented controls.
- Карточки маршрутов вертикальные, без мелких таблиц.
- Фото не должны быть выше всего first viewport.
- FAQ короткий, с раскрывающимися answers.
- 2GIS links должны быть заметны рядом с локациями.

### Performance

- Сжимать фото под mobile.
- Не грузить тяжелые decorative assets.
- Не делать анимации, которые задерживают первый CTA.
- Первый экран должен быть понятен даже на медленном мобильном интернете.

## 11. Proposed page order v2

1. Header + compact hero + booking picker.
2. Route cards with availability language.
3. How booking works.
4. Safety / beginner guidance.
5. Locations with 2GIS links.
6. Real photo proof / source status.
7. Editorial guide cards.
8. FAQ.
9. Final Telegram CTA.

## 12. Definition of done for design v2

V2 можно считать хорошим направлением, если:

- first viewport без скролла показывает цену, длительность, локацию, уровень и Telegram CTA;
- picker виден в первом экране на desktop и сразу после CTA на mobile;
- маршрут можно сравнить за 10 секунд;
- нет фейковых отзывов, фейковой мгновенной брони и чужого proof без прав;
- mobile выглядит как основной сценарий, а не урезанная desktop-страница;
- editorial помогает SEO и выбору, а не украшает страницу;
- admin остается рабочим dashboard, не SaaS-промо;
- дизайн выглядит как сервис, которому можно оставить заявку сегодня.
